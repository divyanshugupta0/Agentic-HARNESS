================================================================================
1. INTRODUCTION
================================================================================

The Node.js Electron-Based Agentic Harness is a desktop application framework
designed to build, deploy, and manage autonomous AI agents locally on a user's
machine. Unlike cloud-only AI tools, this harness runs agent workflows directly
on the desktop, giving users full control over data privacy, tool access, and
execution environment.

The application combines Electron's cross-platform desktop capabilities with
Node.js's backend strength to create a secure, extensible environment where
language-model-driven agents can plan, reason, use tools, and execute
multi-step tasks autonomously or under human supervision.

================================================================================
2. PROBLEM STATEMENT
================================================================================

Existing AI agent platforms are predominantly cloud-based, which raises concerns
about:
- Data privacy and sensitive information leakage to third-party servers
- Vendor lock-in and recurring subscription costs
- Limited access to local system tools (file system, shell, local APIs)
- No native desktop GUI for agent monitoring and control
- Dependency on constant internet connectivity

There is a need for a local-first, desktop-native agentic harness that enables
users to run autonomous agents on their own hardware with full transparency
and local tool integration.

================================================================================
3. OBJECTIVES

================================================================================
5. PROPOSED SYSTEM / SOLUTION
================================================================================

The Agentic Harness follows a layered architecture:

LAYER 1: Presentation (Renderer Process)
- React/Vue or plain HTML/CSS/JS UI inside Electron BrowserWindow
- Agent chat interface, tool permission dialogs, settings panel, log viewer

LAYER 2: IPC Bridge (Preload Script)
- ContextBridge exposes only safe APIs to renderer
- Validates and forwards requests between renderer and main process

LAYER 3: Application Control (Main Process)
- Window management, tray icon, auto-updater, single-instance lock
- IPC handlers for agent lifecycle, file dialogs, system commands

LAYER 4: Agent Engine (Node.js Backend)
- Goal parser and planner
- Tool executor with sandboxing
- LLM client with streaming support
- Memory manager (vector + conversation history)
- Agent scheduler and supervisor

LAYER 5: Tool & Model Providers
- Pluggable LLM providers (REST APIs or local inference)
- Pluggable tools with risk classification (safe, confirm, dangerous)

================================================================================
6. SYSTEM ARCHITECTURE
================================================================================

[Renderer Process] <--> [Preload Script] <--> [Main Process] <--> [Agent Engine]
         UI                 IPC Bridge          App Control         LLM + Tools
                                                        (Electron)       (Node.js)

Key Components:
- main.js: Electron app entry, window creation, IPC handlers
- preload.js: Secure contextBridge API exposure
- renderer/: Frontend UI code
- agents/: Agent definitions, prompts, and workflows
- tools/: Tool implementations (fs, shell, http, etc.)
- memory/: Vector store and conversation memory
- config/: .env, config.json, agents.json
- scripts/: Build, dev, and production scripts

================================================================================
8. KEY FEATURES
================================================================================

1. Autonomous Agent Execution
   - Accept natural language goals
   - Decompose goals into sub-tasks
   - Execute iteratively until goal is met or max steps reached

2. Human-in-the-Loop
   - Approve/reject tool calls before execution
   - Pause/resume agent runs
   - Manual override at any step

3. Local Tool Use
   - File system read/write/search
   - Shell command execution (allowlist/denylist)
   - HTTP API requests
   - Local application control (via Electron)

4. Memory System
   - Short-term conversation memory
   - Long-term vector memory for retrieval-augmented generation (RAG)

5. Multi-Provider LLM Support
   - Switch between cloud and local models
   - API key management via .env

6. Desktop Integration
   - System tray icon
   - Auto-updater
   - Single instance enforcement
   - Native notifications

7. Security
   - contextIsolation enabled
   - nodeIntegration disabled in renderer
   - enableRemoteModule disabled
   - IPC input validation and sanitization

13. INSTALLATION & SETUP
================================================================================

1. Clone the repository:
   git clone <repository-url>
   cd agentic-harness

2. Install dependencies:
   npm install

3. Configure environment:
   cp config/.env.example config/.env
   # Edit .env and add your LLM API keys or set OLLAMA_BASE_URL

4. Run in development:
   npm run dev

5. Build for production:
   npm run build

6. Run installed app:
   - Windows: dist/win-unpacked/AgenticHarness.exe
   - macOS: dist/mac/AgenticHarness.app
   - Linux: dist/linux-unpacked/agentic-harness

15. SECURITY REQUIREMENTS
================================================================================

1. contextIsolation: true (renderer cannot access Node.js APIs directly)
2. nodeIntegration: false in renderer process
3. enableRemoteModule: false (deprecated remote module disabled)
4. Preload script exposes only whitelisted IPC channels via contextBridge
5. All IPC messages validated and sanitized in main process
6. Shell command execution restricted to allowlisted commands
7. File system access limited to user-selected directories
