SECTION 6: BACKEND IPC & API COMMUNICATION VARIABLES (Channels, Payloads, Event Hooks)
====================================================================================================
These variables and channels are implemented in frontend/src/services/api.js, chatService.js, fileService.js,
and context/ChatContext.jsx. They represent the exact API contract for backend developers.

----------------------------------------------------------------------------------------------------
IPC / WEBSOCKET SEND CHANNELS (Frontend -> Backend)
----------------------------------------------------------------------------------------------------
CHANNEL: agent:start
- Invoked in: frontend/src/services/chatService.js (Line 178)
- Payload Variable: content (string) — The user's mission objective or prompt text.
- Additional Context Passed: { modelId: string, tools: Array<string> }
- Purpose: Dispatches autonomous agent execution to Electron main process / local LLM backend.
- When Triggered: When user clicks Send button or presses Enter in chat prompt composer.

CHANNEL: agent:stop
- Invoked in: frontend/src/context/ChatContext.jsx (Line 84)
- Payload Variable: none
- Purpose: Aborts the active running agent process and halts tool execution.
- When Triggered: When user clicks Stop (Square) button during active agent run.

CHANNEL: agent:pause
- Invoked in: frontend/src/context/ChatContext.jsx (Line 89)
- Payload Variable: none
- Purpose: Temporarily pauses agent execution steps and waits for user resume.
- When Triggered: When user clicks Pause button during active agent run.

CHANNEL: agent:resume
- Invoked in: frontend/src/context/ChatContext.jsx (Line 94)
- Payload Variable: none
- Purpose: Resumes a paused agent execution workflow.
- When Triggered: When user clicks Play button on a paused agent.

CHANNEL: file:write
- Invoked in: frontend/src/services/fileService.js (Line 125)
- Payload Variable: { path: string, content: string }
  - path: Absolute or relative virtual file path (e.g. '/config/agent-config.json').
  - content: Full text content of the file.
- Purpose: Writes file modifications to the local operating system disk inside sandbox workspace.
- When Triggered: When user clicks "Save File" button or presses Ctrl/Cmd+S in file editor.

----------------------------------------------------------------------------------------------------
IPC / WEBSOCKET EVENT LISTENERS (Backend -> Frontend)
----------------------------------------------------------------------------------------------------
CHANNEL: agent:log
- Registered in: frontend/src/context/ChatContext.jsx (Line 20)
- Callback Signature: (msg: string | object) => void
- Purpose: Streams real-time execution steps, terminal commands, and tool results from backend to UI.
- When Triggered: Dispatched by backend whenever an agent step executes.

CHANNEL: agent:result
- Registered in: frontend/src/context/ChatContext.jsx (Line 23)
- Callback Signature: (resultPayload: object) => void
- Purpose: Notifies UI that agent has finished execution; automatically sets agentStatus to 'idle'.
- When Triggered: Dispatched by backend upon agent completion or final error.

CHANNEL: agentic:event
- Registered in: frontend/src/services/api.js (Line 57)
- Detail Schema: { channel: string, data: any }
- Purpose: Browser-compatible fallback dispatch mechanism when testing outside of Electron runtime.

SECTION 10: BACKEND BINDING & ENDPOINT MAPPING BLUEPRINT
====================================================================================================
To connect this frontend to your Node.js, Python FastAPI, Go, or Electron backend, implement the following
equivalent endpoints or IPC handlers:

----------------------------------------------------------------------------------------------------
1. AUTHENTICATION SERVICE BINDING
----------------------------------------------------------------------------------------------------
- POST /api/auth/signin (or IPC: 'auth:signin')
  - Request: { email: string, password: string, rememberMe: boolean }
  - Response: User object { id, name, email, avatar, role, isAuthenticated, lastLogin }
  - Frontend Hook: authService.signIn() -> AuthContext.signIn()

- POST /api/auth/signup (or IPC: 'auth:signup')
  - Request: { name: string, email: string, password: string }
  - Response: User object { id, name, email, role: 'Member', isAuthenticated, createdAt }
  - Frontend Hook: authService.signUp() -> AuthContext.signUp()

- POST /api/auth/signout (or IPC: 'auth:signout')
  - Request: none
  - Response: Guest User object { id: 'guest', isAuthenticated: false }
  - Frontend Hook: authService.signOut() -> AuthContext.signOut()

----------------------------------------------------------------------------------------------------
2. AGENT RUNNER & CHAT BINDING
----------------------------------------------------------------------------------------------------
- POST /api/chat/conversations (or IPC: 'chat:create')
  - Request: { title: string }
  - Response: Conversation object { id, title, updatedAt, messages: [] }

- POST /api/agent/start (or IPC: 'agent:start')
  - Request: { conversationId: string, content: string, modelId: string, tools: Array<string> }
  - Streaming Response / Socket Events:
    - Event 'agent:log': { step: string, output?: string, timestamp: string }
    - Event 'agent:result': { finalContent: string, executionSteps: Array<string>, thinking: string }
  - Frontend Hook: chatService.sendMessage() -> ChatContext.sendMessage()

- POST /api/agent/pause (or IPC: 'agent:pause')
  - Purpose: Halts agent worker execution loop.
  - Frontend Hook: ChatContext.pauseAgent()

- POST /api/agent/resume (or IPC: 'agent:resume')
  - Purpose: Resumes agent worker loop.
  - Frontend Hook: ChatContext.resumeAgent()

- POST /api/agent/stop (or IPC: 'agent:stop')
  - Purpose: Forcibly kills spawned agent child process or sandbox container.
  - Frontend Hook: ChatContext.stopAgent()

----------------------------------------------------------------------------------------------------
3. FILES & SANDBOX BINDING
----------------------------------------------------------------------------------------------------
- GET /api/files (or IPC: 'files:list')
  - Response: Array<WorkspaceFile>
  - Frontend Hook: fileService.getFiles() -> WorkspaceContext.files

- POST /api/files/write (or IPC: 'file:write')
  - Request: { path: string, content: string }
  - Response: { success: boolean, updatedAt: string }
  - Frontend Hook: fileService.saveFile() -> WorkspaceContext.saveActiveFile()

- DELETE /api/files/:id (or IPC: 'file:delete')
  - Request: { id: string }
  - Response: { success: boolean }
  - Frontend Hook: fileService.deleteFile() -> WorkspaceContext.deleteFile()

----------------------------------------------------------------------------------------------------
4. EXTENSIONS & MARKETPLACE BINDING
----------------------------------------------------------------------------------------------------
- GET /api/plugins (or IPC: 'plugins:list')
  - Response: Array<Plugin>
  - Frontend Hook: pluginService.getPlugins()

- PATCH /api/plugins/:id (or IPC: 'plugin:update')
  - Request: { installed?: boolean, enabled?: boolean, config?: object }
  - Response: Updated Plugin object
  - Frontend Hook: pluginService.updatePluginConfig(), toggleInstall(), toggleEnabled()
